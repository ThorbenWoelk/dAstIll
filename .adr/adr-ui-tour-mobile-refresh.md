# ADR: UI Tour Mobile Refresh

## Decision

Treat the UI Tour as a mobile-web-first doc and keep the in-product guide aligned with that same flow.

## Context

The existing UI Tour content is current enough to describe the product family, but not current enough to reliably orient a new user on a phone. The docs page still centers desktop screenshots, and the guide copy carries older positioning language.

## Alternatives considered

- Keep the desktop-led tour and only update the capture date.
- Refresh screenshots only, without changing the narrative.
- Split the tour into separate mobile and desktop docs pages.

## Consequences

- The docs become more representative for common first-contact usage on the web.
- Desktop still needs brief coverage, but it is no longer the main narrative.
- Future UI Tour refreshes should update screenshots and guide copy together.

## Follow-ups

- Consider a reusable screenshot capture workflow for docs maintenance.
- Consolidate mobile UX findings into a clearer roadmap artifact when those product changes are scheduled.
