# Frontend Agent Guide

Short entry point for agents working in `frontend/`. Design and engineering rules live in [../design.md](../design.md). Read that first.

## What this is

A static SvelteKit single-page app: the dAstIll reader. It shows subscribed channels' video summaries as a morning paper and talks to the backend through `src/lib/api.ts`.

## Structure

- `src/routes/` — `/` (reader), `/sections` (follow or unfollow channels), layout with the sign-in gate
- `src/lib/api.ts` — every backend request
- `src/lib/session.svelte.ts` — Firebase Google sign-in
- `src/lib/edition/` — pure reader logic plus the `EditionReader` state class
- `src/lib/components/` — presentational components and `icons/`
- `src/lib/bindings/` — generated by backend `cargo test` (`ts-rs`); do not edit
- `tests/` — Bun unit tests
- `e2e/` — Playwright specs with a mocked backend

## Responsive parity

When you edit a base CSS rule or a breakpoint block, run the Playwright specs at both phone and desktop sizes before committing. See [../design.md#testing](../design.md#testing).

## Verification before commit

From `frontend/`:

1. `bun install --frozen-lockfile`
2. `bun run format:check`
3. `bun run lint`
4. `bun run check`
5. `bun run test`
6. `bun run test:e2e`
7. `bun run build`
8. `bun audit --production`

All green. No exceptions.
