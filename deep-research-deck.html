Repo briefing

dAstIll is a reading system with an AI pipeline behind it.

It starts from subscribed sources, turns source material into readable summaries, evaluates those summaries, and keeps search and chat grounded in rebuildable evidence.

Rust backend SvelteKit UI Ollama models S3 plus libSQL Firebase hosting

Central thesis

The product is not a video app. It is a trustable distillation loop.

Input

Subscriptions and source definitions from YouTube, OpenAlex, podcasts, and websites.

Transformation

Transcripts, abstracts, notes, or page text become summaries, evaluations, chunks, embeddings, and FTS records.

Output

Workspace reading, highlights, search, grounded chat, mini reading, and optional summary audio.

The quiet invariant: canonical content must survive even when AI, indexing, search, or cloud services are tired.

Sources: docs/architecture/overview.md:48-57, docs/pipelines/content-pipeline.md, docs/pipelines/ai-models.md:341-352.

Pipeline

Canonical content is written first. Expensive work follows behind it.

Discoversource input, channel resolution, video discovery
Extracttranscript text, timed captions when available
Distillsummary generation, manual edits, evaluator score
Projectsearch_sources, chunks, FTS, vectors
Why this matters

Search, embeddings, evaluation, and external model calls are failure-prone. The code keeps them out of normal CRUD writes.

What can degrade

Canonical content can succeed while search is offline. Evaluation can pause without blocking search. Transcript failures do not corrupt videos.

Sources: docs/architecture/overview.md:120-143, docs/pipelines/content-pipeline.md:33-47, docs/pipelines/content-pipeline.md:162-190.

Data model

There are three kinds of state. Mixing them is where bugs begin.

Canonical records

channels, videos, transcripts, summaries, and video_info describe source truth.

User overlays

Subscriptions, read/acknowledged state, highlights, and chat live under user-scoped records or tables.

Derived projections

Search chunks, vector embeddings, keyword rows, and audio cache can be rebuilt from canonical content.

The API intentionally merges canonical and user-scoped records into view models, but the storage model keeps their ownership separate.

Sources: docs/architecture/data-model.md:43-82, docs/architecture/data-model.md:83-105, docs/architecture/data-model.md:107-164, docs/architecture/data-model.md:166-235.

Runtime topology

The backend is both API server and worker host.

5sQueue worker

Advances transcript and summary work.

30mRefresh worker

Fetches latest subscribed content.

7sEvaluator worker

Scores summaries and requeues low-quality ones.

3sSearch worker

Backfills, indexes, reconciles, and prunes projection rows.

AppState is the boundary. It holds storage, auth, rate limiters, workers, services, cooldowns, search locks, active chats, and model adapters.

Search architecture

Search is a hybrid retrieval system with graceful partial failure.

Keywordlocal libSQL FTS5, BM25, title and section signal
SemanticS3 Vectors with Ollama embeddings when enabled
FusionReciprocal Rank Fusion combines candidate lists
Rerankoptional cross-encoder through Ollama
Index lifecycle

Ready transcript and summary content becomes pending search sources. The worker chunks, embeds when available, writes S3 chunks, and syncs FTS rows.

Retrieval metadata

Chunks retain source kind, video/channel metadata, section titles, and optional start_sec for timed transcript navigation.

Sources: docs/pipelines/search-indexing.md:47-80, docs/pipelines/search-indexing.md:84-130, docs/pipelines/search-indexing.md:134-190, backend/src/services/search/mod.rs:15-18.

Chunking

The chunker protects recall without letting one transcript dominate the index.

300Target words

Transcript and summary chunks target 300 words.

40Overlap words

Transcript chunks carry overlap across boundaries.

80Hard cap

Transcript and summary sources cap chunk counts at 80.

Design choice

Summaries always keep a full-document chunk, then add section chunks. Timed transcript chunks carry start_sec; paragraph transcript chunks leave it null.

Sources: docs/pipelines/search-indexing.md:178-242, backend/src/workers/mod.rs:69-105.

Chat and RAG

Chat plans retrieval before it speaks.

Planner

Classifies the user message into fact, synthesis, pattern, comparison, recommendation, or recent-activity style work, then chooses query fan-out and budgets.

Retriever

Runs FTS and semantic retrieval, assembles scored context, truncates source snippets, and stores attribution with assistant messages.

Model contract

Model roles are separate on purpose.

RoleConfigWhy separate
SummarizerOLLAMA_SUMMARY_MODELGenerates summaries and cleans transcripts through Ollama generate.
FallbackOLLAMA_FALLBACK_MODELCan run local fallback when cloud-backed summarizer is rate-limited.
EvaluatorSUMMARY_EVALUATOR_MODELMust be a separate cloud model so generation and judgment stay independent.
EmbeddingOLLAMA_EMBEDDING_MODELPowers semantic search and disables quietly when unavailable.
Rerank and HyDESEARCH_RERANK_MODEL, SEARCH_HYDE_MODELOptional precision and recall upgrades for hybrid search.

Startup rejects identical summarizer and evaluator model strings. That small guard enforces the larger trust idea.

Security posture

The agentic surface is bounded retrieval, not tool-executing autonomy.

Controls in place
  • Chat treats retrieved excerpts and tool outputs as untrusted data.
  • Chat tools are schema-bounded, read-only, and step-limited.
  • Retrieval is scoped to the caller's accessible library.
  • Expensive routes and anonymous chat have rate-limit and quota hooks.
Known gaps
  • Rate limiting is still process-local.
  • ASI red-team testing is not automated in CI.
  • Tool-call audit logging and supply-chain review still need work.

Sources: docs/security/index.md, backend/src/main.rs:493-521, backend/src/main.rs:540-547, backend/src/main.rs:715-722.

Invariants

These are the rails a maintainer should not bend casually.

Content and search
  • Canonical content before derived projections.
  • Async workers over inline embedding, chunking, and model-heavy work.
  • FTS should continue when semantic search is disabled or unavailable.
  • Search rebuilds coordinate through the projection lock.
Auth and operations
  • Resolve AccessContext before library access decisions.
  • Do not put app secrets in Terraform state or startup scripts.
  • Production backend scale-out is blocked by current in-process worker/cache design.
  • Frontend design changes belong in design.md first.
