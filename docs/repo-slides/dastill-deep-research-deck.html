Central thesis

The app turns feed anxiety into a searchable, evaluated library.

The product watches sources, turns raw media or web text into readable artifacts, scores the AI output, and lets the user return through summaries, highlights, search, audio, or chat.

Sources: README.md; docs/architecture/overview.md

Runtime topology

Only the backend owns durable changes and worker execution.

Browser Uses SvelteKit product UI and VitePress docs UI.
Frontend Calls the Rust backend directly with Firebase bearer tokens or trusted proxy headers.
Backend Owns storage clients, local libSQL, API handlers, AI services, and long-running workers.
Workers Advance queues, refresh feeds, evaluate summaries, and maintain search projections.
Sources: docs/architecture/runtime-topology.md; docs/architecture/frontend-and-api.md
Startup model

Startup binds early, then assembles a single shared state object.

  1. Load environment and runtime configs.
  2. Initialize AWS, S3, S3 Vectors, and local libSQL.
  3. Build service adapters for sources, AI, TTS, chat, and search.
  4. Hydrate search progress and FTS when needed.
  5. Spawn worker loops and bind API routes.

AppState is the pressure point.

It carries the store, read cache, rate limiter, projection lock, FTS index, source services, AI services, chat service, mobile handoff sessions, cooldowns, and analytics client.

Sources: backend/src/main.rs; backend/src/state.rs; docs/architecture/runtime-topology.md
Storage invariant

Canonical content is sacred. Search is rebuildable.

Channels, videos, transcripts, summaries, and video info are the source records. Search sources, chunks, keyword rows, and vector embeddings are projections that workers can recreate.

Canonical User overlay Derived
Channels, videos, transcripts, summaries, video info. Subscriptions, acknowledgements, preferences, highlights, conversations. Search sources, chunks, BM25 rows, embeddings, summary audio cache.
Sources: docs/architecture/data-model.md; backend/src/db/*
Content pipeline

The expensive work moves in the background.

Input YouTube, OpenAlex, podcast RSS, or website page.
Canonicalize Resolve source, create metadata, and queue content states.
Extract Transcript or text extraction uses summarize, with yt-dlp json3 fallback for timed captions.
Distill Summaries are generated only after transcripts are ready, then evaluated by a separate model.
Index Writes mark search work pending; the search worker chunks, embeds, and updates FTS later.
Sources: docs/pipelines/content-pipeline.md; backend/src/workers/mod.rs
AI roles

Model separation is part of the product contract.

Role Config Why it matters
Summarizer OLLAMA_SUMMARY_MODEL Creates and cleans content through Ollama /api/generate.
Evaluator SUMMARY_EVALUATOR_MODEL Must differ from the summarizer, and startup fails if they match.
Embedding OLLAMA_EMBEDDING_MODEL Powers semantic search when enabled; FTS continues without it.
Chat OLLAMA_DEFAULT_CHAT_MODEL Runs grounded conversations with retrieval budgets by intent.
Sources: docs/pipelines/ai-models.md; README.md; backend/src/main.rs
Search model

Hybrid search is two retrieval legs plus rank fusion.

Keyword libSQL FTS5 BM25 with title, section, source, channel, and timestamp metadata.
Semantic Optional S3 Vectors ANN or exact vector scan, backed by Ollama embeddings.
Fusion Reciprocal Rank Fusion merges the legs; optional reranking can rescore top candidates.
Surface Results group by video and keep one best match per source kind where possible.
Sources: docs/pipelines/search-indexing.md; backend/src/services/search/*
Chat RAG

Chat is retrieval planning, not a single search call.

The chat service classifies intent, expands queries across passes, retrieves keyword and semantic candidates, assembles context, then streams a response with sources.

Sources: docs/pipelines/ai-models.md; backend/src/services/chat/*

Frontend architecture

  • frontend/src/lib/api.ts owns product request helpers and cache invalidation.

Operations

Local and production paths are deliberately different.

Local Production
./start_app.sh runs frontend on 3543, backend on 3544, docs on 4173, and optional Android. Cloud Run serves backend; Firebase Hosting serves product frontend and docs.
Shared env lives under ~/.config/dastill/; AWS credentials should live outside repo env files. Secret Manager holds sensitive payloads; Cloud Run env holds non-secret runtime config.
Debug builds default semantic search on unless overridden. Release defaults semantic search off unless explicitly enabled.

Analytics

Databricks is a separate analytics plane.

The backend can write analytics events to a Bronze table. The Databricks bundle defines a triggered pipeline that deduplicates Silver events and builds Gold views for processing, engagement, and summary consumption dashboards.

Bronze Backend-written app events.
Silver Typed, deduplicated app events in a private materialized view.
Gold Dashboard-facing processing, engagement, and consumption views.

Dangerous edges

The system has clear invariants. Break them slowly.

  • Do not inline expensive work into writes. Queue it, mark pending, let workers advance it.
  • Do not treat browser storage as canonical. Scope every local cache by auth context.
  • Do not store secret payloads in Terraform state or repo files. Terraform owns containers and IAM, not payloads.
  • Do not scale backend replicas casually. In-process workers and local libSQL cache make one serving instance the current production assumption.
  • Do not make the evaluator the summarizer. The startup guard exists to keep judgment independent.
